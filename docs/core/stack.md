# Unified Stack における Call Frame 実装のまとめ

> Status: historical design note. The current runtime memory and execution
> contracts are documented in [runtime-memory.md](runtime-memory.md). Treat this
> file as background for earlier stack-layout work, not as the current ABI.

## 概要

本ドキュメントでは、Wasm 実装における Unified Stack（統合スタック）モデルの構造、利点、課題について記述する。

---

## スタック構造（我々の実装）

統合スタック上において、Call Frame は以下の順序で構成される。

```
+-------------------------------------------------------------+
|             Call Frame n (最上位)                           |
|-------------------------------------------------------------|
|  [ Locals/Params ]          ← ローカル変数・引数領域         |
|  [ Prev Frame Start Addr ]  ← 前のCall Frameの開始位置        |
|  [ Return Addr ]            ← 戻り先アドレス                 |
|  [ Operand Data ]           ← 一時的な計算用スタック領域       |
+-------------------------------------------------------------+
|             Call Frame n-1                                  |
|  ...                                                        |
+-------------------------------------------------------------+
```

- フレームは下方向に成長。
- フレーム間は `Prev Frame Start Addr` によって連結されている。

---

## 実装の特徴

### 1. 一元的なスタック領域
- すべての Call Frame を同一スタック上で管理。
- メモリレイアウトが単純でキャッシュローカリティが良好。

### 2. Locals/Params の先行配置
- ローカル変数・引数がフレームの先頭に配置され、効率的にアクセス可能。

### 3. 前フレーム開始位置の記録
- 戻る際のスタックポインタの巻き戻しが簡潔。
- 戻り処理が一定で、分岐が不要。

### 4. 明示的な Return Addr 管理
- 戻り先アドレスがフレームに記録されており、復帰処理が明確。

### 5. Operand Data の局所化
- 計算中の一時データは各フレーム内に保持され、破棄も簡潔。

### 6. スタックトレース生成が容易
- フレームリンク構造により、フレームのトレースや例外時の復元がしやすい。

---

## 課題・トレードオフ

### 1. フレームサイズの可変性
- Call Frame のサイズが固定でないため、フレームの再利用やキャッシュが困難。

### 2. 巻き戻しの固定性
- Prev Frame Start Addr に依存しているため、例外処理や非同期制御と相性が悪い。

### 3. メモリオーバーヘッド
- 各フレームで前フレーム開始位置を記録する分、わずかに余分なメモリを使用。

### 4. GCとの相互作用
- スタックスキャン時にフレーム構造の解釈が必要。
- 参照型の取り扱いに追加の考慮が必要となる。

### 5. スタックトレースの情報量
- フレーム自体には関数名やデバッグ情報が含まれていないため、別途情報管理が必要。

### 6. 非同期処理・スレッドとの制約
- 連続したスタックとフレームリンクは、コルーチンや中断可能な関数と直接の互換性がない。

---

## まとめ

この実装は、通常の関数呼び出し・戻りに対してシンプルかつ効率的なスタック管理を提供する。一方で、柔軟性の要求される機能（例外処理・GC・非同期制御）との統合には設計上の工夫が必要となる。
