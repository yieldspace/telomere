# Core Wasm Runtime の処理概要

## 概要

この文書では `crates/telomere/src/runtime` 以下で実装されているコア WebAssembly ランタイムの基本的な処理の流れをまとめる。モジュールのインスタンス化から命令実行、メモリ管理まで、主要なコンポーネントの役割を俯瞰することを目的とする。

## 主なコンポーネント

- **instantiate**: モジュールを読み込み、他のインスタンスとのリンクを解決して `InstanceHandle` を生成する。
- **vm**: 実行コンテキストと命令ハンドラを提供する。各命令は関数ポインタとして定義され、スタック操作やメモリアクセスを行う。
- **scheduler**: 非同期ホスト関数やメモリ操作の待機処理を管理する。タスクをキューに登録し、再開条件が満たされると VM の実行を続行する。
- **memory_effect**: メモリの読み書きに伴う効果を抽象化する。非同期実行時にはここで待機フラグを設定することで、スケジューラと連携する。
- **trace**: デバッグ用のトレースを出力するマクロを提供する。

## 処理の流れ

1. **モジュールのインスタンス化**
   1. `instantiate` 関数が `Module` または `NativeModule` を受け取り、インポートの解決やデータ/エレメントセクションの初期化を行う。
   2. グローバル変数、メモリ、テーブル、関数体が `GcRef` としてヒープに配置され、`InstanceHandle` が生成される。

2. **実行の開始**
   1. `run_module_function` などの API を通じて実行エントリが呼び出される。
   2. `vm` モジュールが `ExecuteContext` を初期化し、スタックやローカル変数領域を確保する。
   3. 命令列は事前に解析され、各命令は対応するハンドラ(`op_i32_add` など)へのポインタとして並べられている。

3. **命令ループ**
   1. `call_code`/`call_next` 関数により、現在の命令ポインタからハンドラを呼び出して処理を進める。
   2. `wait_effect!` マクロにより、メモリ操作などで待機が必要な場合はスケジューラに制御を戻し、後続の命令アドレスを保持する。
   3. 戻り値は `ResultValue` として収集され、スタックの内容が呼び出し元に返される。

4. **メモリ管理と GC**
   - `gc.md` で述べられているように、ランタイムは Lisp2 に基づくマーク・コンパクト GC を用いる。
   - `InstanceData` や `FunctionInstanceData` などのオブジェクトはヒープ上に確保され、`GcRef` 経由で参照される。
   - GC サイクル中はルートセットとして実行スタックや登録済みインスタンスがスキャンされる。

5. **非同期実行**
   - スケジューラは `ReadyFlag` を用いてタスクの待機状態を管理する。ホスト関数が `AsyncEffect` を返す場合、対応するフラグが立つまで VM は一時停止する。
   - `special_function_return` などのエントリポイントから再開し、保留中の命令を続行する。

## まとめ

以上のように、core wasm runtime はモジュールのロードから実行、メモリ管理、非同期処理までを一貫して扱う。各コンポーネントは疎結合であり、VM の中心となる `vm` モジュールを基点に、インスタンス化・スケジューリング・メモリ効果が連携して動作する設計となっている。
